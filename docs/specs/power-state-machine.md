# 功率状态与读数来源

## 规则

1. 系统明确报告 Battery Power 时，适配器输出为零，忽略旧的适配器字典。
2. 系统明确报告 AC Power 时，保留电池与适配器混合供电的可能性。
3. 电源类型读取失败时，才使用 AppleSmartBattery 的 ExternalConnected；仍未知则不宣称充电或放电。
4. 适配器实时功率来自有效的 SMC 电压×电流，或 BatteryData.AdapterPower。额定功率只展示供电能力。
5. 电池控制器的带符号电流决定电池方向。适配器与系统 SMC 功率可能来自不同功率域或时间窗口；两者无法与电池功率闭合时保留各自实测值，图中适配器分支由系统负载与已确认的电池方向计算，不据此改写电池方向或显示诊断状态。只有电池电流缺失且电池可读取时，才使用输入与系统的差值估算电池功率。
6. 缺少其中一个功率读数时，可使用有效的带符号电池电流推算；如果结果为负或超出范围，则保留不可用状态。
7. 零电流与缺失电流不同。NaN、无穷和非法读数不得流入图形或整数格式化。

## 展示状态稳定

功率计算保留每次有效采集的原始带符号电池功率；界面方向另由有状态 reducer 确认：

- 电池功率严格大于 1.0 W 或小于 −1.0 W 才进入充电或辅助供电候选；已确认方向在同向功率超过 0.5 W 时保持。
- 候选必须由四次不同 acquisition ID 的电池采集组成，且首尾至少跨越六秒。界面刷新重复消费同一缓存不会推进确认。
- 绝对值不超过 0.5 W 的连续样本确认成“电池基本闲置”；0.5–1.0 W 显示“低功率活动”，不声明方向。
- 候选反向时立即暂停旧方向动画并重新确认。电源来源切到 Battery Power 时立即生效，不等待防抖。
- 缺失、冲突、长采样空档及睡眠唤醒不沿用旧方向。
- 未确认方向时保留瞬时功率文本，但不把它绘制成充电或放电能量流。
- 确认中、读数缺失或冲突均不替换用户选择的主视图，也不显示传感器诊断文案。
- 最近一分钟趋势使用未经阈值截断的带符号功率积分，持续微小净放电不会被“基本闲置”标签抹去。

这些规则只稳定展示，不改变 macOS 的实际充放电，也不推断充电器不足或硬件故障。未确定的 0–5 W 波动见[已知问题 KI-001](../known-issues.md)。

## 场景

| 场景 | 结果 |
| --- | --- |
| 适配器 50 W / 系统 30 W | 充电拓扑，电池约充入 20 W |
| 适配器 20 W / 系统 30 W | 混合供电拓扑，电池约补足 10 W |
| 适配器 30 W / 系统 30 W | 旁路，电池 0 W |
| 已拔线，但电池字典仍有适配器 | 适配器 0 W，纯电池供电 |
| 只有额定 65 W，实时功率缺失 | 系统功率不可用，不显示 65 W |
| 适配器 12.8 W / 系统 25.2 W / 电池电流 0 | 显示适配器输入 12.8 W、系统消耗 25.2 W、电池闲置；图中适配器分支按 25.2 W 绘制 |
| 拔线后仍收到正向充电电流，系统功率缺失 | 不宣称充电；功率等待更新 |

只有在电池电流缺失而需要差值估算时，计算结果才按适配器输入 + 电池放出 = 系统消耗 + 电池充入进行账面闭合。三路均为实测时不强行协调跨功率域的数值。

回归场景在 `Tests/MacStatusCoreTests/PowerCalculationTests.swift`，包含 841 组适配器/系统功率组合。
