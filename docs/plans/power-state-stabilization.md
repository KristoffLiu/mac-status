# 小功率充放电切换：分析与展示优化方案

日期：2026-09-17。状态：核心实现与自动化验证完成；物理根因和跨机型阈值仍待真机数据确认，跟踪于 [KI-001](../known-issues.md)。

## 实施记录

已实现采集 ID 与单调时间、展示状态 reducer、1.0/0.5 W 滞回、四次且六秒确认、生命周期重置、四种视图的统一方向、确认期中性概要，以及最近一分钟带符号趋势。实现没有提高既有采样频率。

自动化回放覆盖缓存重复、正负交替、小功率闲置、持续辅助供电、反向、拔线、估算读数、生命周期重置和一分钟积分；应用 Debug 构建通过。下文保留完整设计与验收依据，其中诊断采集字段拆分和跨机型真机调参仍属于 KI-001 的后续调查，不属于本次展示稳定性修复已解决的内容。

## 结论与证据边界

用户观察到：连接 96 W 电源时，电池在充电、放电、零功率之间不时变化，幅度约 0–5 W。

当前能够确认的是：应用把瞬时电池功率的符号直接映射为供电状态，缺少时间确认和滞回。它会放大短时变化的视觉影响。“混合供电”本身不证明充电器功率不足。尚不能确认用户观察到的每一次变化是真实充放电、测量波动还是采样时序差异。

本次交付核验：已重新检查当前工作树的采样、计算、调度及所有能量流视图的消费路径；完整 `swift test` 的 44 项测试通过，其中包括 841 组功率守恒组合、11 项展示状态/趋势序列测试和 2 项跨功率域回归。应用 Release 构建通过。自动化证据不代替跨机型真机调参或 KI-001 的物理根因调查。

证据如下：

| 证据 | 已验证的内容 | 不能据此推断的内容 |
| --- | --- | --- |
| 本次会话约 30 秒及随后约 60 秒的 AppleSmartBattery / pmset 只读采样 | 已接 AC，电量 80%，瞬时与 Amperage 字段均为 0；第一次输入约 28 W、系统约 26–28 W；第二次 31 次读取电流均为 0 | 未捕获用户所述波动；不能证明其他时刻也没有放电 |
| 直接编译生产计算类，用 12 V 电池、30 W 系统负载回放带符号电池功率 | +0.12 W 输出充电，−0.12 W 输出放电且存在适配器，0 W 输出闲置；±2 W、±5 W 同样随符号切换。该回放没有提供适配器实测功率，计算层会将其估算并标记 | 这是分类逻辑复现，不是真机电流变化的复现 |
| 当前工作树源码复核 | BatteryService 优先使用 InstantAmperage；计算层按正负号分类；展示层直接消费结果 | IOKit 字段名不能证明硬件采样率、滤波时间常数或测量精度 |
| 电量为 80% | 与充电管理场景相容 | 不能确认启用了充电上限、优化充电或第三方控制，也不能用其解释每次瞬时切换 |

排查顺序：先确认发生切换时的原始电池电流与 UI 是否一致；再区分真实的短时充放电与传感器/采样差异；只有捕获到持续净放电，才进一步调查实际输入能力及充电管理策略。当前没有证据要求更换电源或修改系统充电设置。

## 当前实现与约束

- [BatteryService](../../MacStatus/MacStatus/Services/BatteryService.swift) 将 InstantAmperage 优先写入 amperage；Amperage 仅作为回退，并未单独保留。不能直接把后者改称“已验证的平均电流”。
- [PowerSampler](../../MacStatus/MacStatus/Services/PowerSampler.swift) 约两秒刷新一次电池缓存；SMC 随每次调用读取，来源可能不同步。供电来源切换绕过缓存。
- [SamplingPolicy](../../MacStatus/MacStatus/Models/SamplingPolicy.swift) 支持前台 0.2–2 秒、后台 2–20 秒 tick，后台默认 10 秒。UI 刷新次数不等于电池新读数数量。
- [PowerCalculationService](../../MacStatus/MacStatus/Services/PowerCalculationService.swift) 是无状态数值计算；电池方向以电池控制器为准，跨功率域差额不参与电池方向判断。原始适配器输入继续展示，能量流中的适配器分支按系统负载与已确认的电池方向计算。估算标识和额定功率不参与实时计算等规则详见[现有规范](../specs/power-state-machine.md)。
- [PowerTopology](../../MacStatus/MacStatus/Models/PowerTopology.swift) 的 batteryPower 为绝对值，方向来自布尔值。冲突时方向布尔值会清除，所以不能从此对象无损恢复原始带符号功率。
- [StatusViewModel](../../MacStatus/MacStatus/StatusViewModel.swift) 直接发布每次计算；卡片、桑基、方块、设备视图及菜单栏电池图标均使用其方向或拓扑。

## 产品行为

将外部电源连接状态与电池活动拆开表达，示例：

- `外接电源 · 电池基本闲置`
- `外接电源 · 电池充电`
- `外接电源 · 电池辅助供电`
- `外接电源 · 电池方向确认中`（出现反复反向时可用“电池短时波动”）
- `外接电源 · 电池低功率活动`（未达到方向确认阈值，但非近零）
- `电池供电`
- `外接电源 · 电池读数暂不可用` / `传感器读数暂不一致`

“基本闲置”只表示落入展示容差，不表示电流精确为零，也不证明内部电路的“旁路”拓扑。电池辅助供电不附带“充电器不足”的原因判断。

实时数字保留，明确标注“瞬时充入/放出”；趋势另标“近 1 分钟净充入/放出（估算）”。系统 IsCharging 作为辅助诊断字段，既不单独证明电池正在放电，也不作为强制覆盖实测方向的开关。

## 推荐实现：三层分离

### 1. 采样与物理计算

保持数值计算服务无状态，不为防抖修改原始电池电流、功率守恒公式、估算质量或现有拓扑。额定 96 W 不参与实时方向判定。

扩展采样快照，保留：

- 独立的 InstantAmperage、Amperage 及实际采用的字段来源；缺失与零区分。
- 原始带符号电池功率（正为充入、负为放出），以及有效性、质量。
- 每次成功读取的递增 acquisitionID、单调采集时间、电源来源；SMC 另有采集时间。
- 若能验证硬件时间戳/序号语义，则另保留硬件标识。现有 sampledAt 是应用读取时间，不是硬件转换时间。

重复使用同一 acquisitionID 的电池缓存不得增加确认次数、更新 EMA 或累计能量。不同 acquisitionID 的相同数值可以是稳定观测，不能仅按“值未改变”判为旧数据；同样不能把重新读取 IORegistry 宣称为独立硬件测量。

仅依靠适配器与系统差值估算的电池方向，不升级为“已实测确认”的辅助供电。详情保留带 `≈` 的估算；主状态标明方向为估算，默认不启用已确认方向动画。适配器与系统读数跨域不触发冲突页；物理不可能的电池/电源组合仍由冲突提示处理。

### 2. 展示状态确认

新增可独立测试的 PowerPresentationReducer，由 StatusViewModel 持有实例。输入为快照、现有计算结果、采样策略和注入的单调时间；输出为 PowerPresentationState。它不读取硬件、不建立计时器、不使用全局共享状态。

以下为第一轮候选参数，不是 Apple 规范或已测出的本机噪声边界：

| 参数 | 初值 | 用途 |
| --- | --- | --- |
| 方向进入阈值 E | 1.0 W | 大于 E 才开始确认充电，小于 −E 才开始确认辅助供电 |
| 方向保持/近零阈值 X | 0.5 W | 已确认方向在同向且幅度大于 X 时可以保持；绝对值不超过 X 是基本闲置候选 |
| 最小观测跨度 | 6 秒 | 排除短时脉冲 |
| 最小成功采集次数 | 4 次 | 排除单点与缓存重复；常见两秒间隔对应 t=0、2、4、6 |
| 单段允许采样间隔 | 2 × 预期电池采集间隔 + 1 秒 | 超过则视为采样中断，重置候选与滤波历史 |
| 趋势 EMA 时间常数 | 5 秒 | 只用于趋势展示，第一版不叠加到状态确认前 |

预期电池采集间隔取 max(2 秒, 当前策略 tick 间隔)。前台确认通常约 6 秒，后台默认至少四次读取、约 30 秒；这些只表示观测到的趋势，不声称采样间隔内每一刻都在同向流动。保持现有后台频率，不为满足前台响应时间提高后台采样率。

状态更新按以下优先级处理：

1. 电源切换优先处理，不能被缓存去重挡住。检测到拔线的这一轮立即显示电池供电并清除 AC 候选；插线立即显示外接电源，电池方向重新确认。实际延迟受系统通知/下一次采样限制，不承诺物理事件发生瞬间即可获知。
2. 来源未知、无有效电池电流、冲突或过期时，撤销展示方向并清除候选。无效样本不得当零输入，旧状态不能一直挂在屏幕上。功率图仍遵守现有 isComplete 限制。
3. 新采集的有效实测 P 才推进候选。未确认时：P > E 为 charging 候选，P < −E 为 assisting 候选，abs(P) <= X 为 idle 候选。X < abs(P) <= E 显示 lowActivity，重置候选确认计数。
4. 同一候选达到“四次新采集且跨度至少六秒”才提交为稳定状态；换候选则从该样本重新计时计数。额外收到缓存 tick 不改变进度。
5. 已确认 charging 时，P > X 保持；已确认 assisting 时，P < −X 保持。这就是进入与退出阈值不同的滞回。idle 在 abs(P) <= X 时保持。
6. 不再满足保持条件时，立即暂停方向展示，按第 3 条开始新候选确认。可内部保留 lastConfirmed 用于诊断，但不可继续把旧方向当成当前事实，也不可用它绕过新候选确认。正负互换不能沿用旧箭头。
7. 睡眠/唤醒、前后台采样策略改变、长采样空档时，清空候选和 EMA，重新确认；供电连接状态仍优先更新。使用单调时钟，不因系统时间校正累计虚假持续时间。

显示优先级：冲突/不可用 > 确认中/低功率活动 > 已确认方向。单点大功率变化仍显示真实瞬时瓦数，但不新增未经验证的“强变化快速通道”。拔线无需等待方向确认。

### 3. 一致的图形与趋势

所有四种视图和菜单栏共用同一个 presentation 对象。不能只替换卡片状态文字，留下桑基布局、设备颜色或菜单栏闪电图标随原始符号切换。

- 方向确认中、低功率活动、基本闲置：使用固定电池节点和中性连接，暂停电池方向动画；数值仍显示带方向的瞬时读数。
- 已确认充电/辅助供电且当前数据有效：启用相应箭头和颜色。
- 桑基/方块图在待确认时使用中性数值概要，避免用“旧方向 + 新功率”绘制守恒图；不把真实电池功率置零来凑平衡。
- 不使用平滑后的电池功率搭配未经同步平滑的适配器/系统功率绘制守恒图。第一版仅对独立趋势显示做 EMA，主功率读数沿用现有计算和质量标记。
- 趋势 EMA 使用 alpha = 1 − exp(−dt / tau)，仅在新有效采集到达时更新；缺失、重复、跨睡眠/电源切换的样本不推进。
- 菜单栏在外接电源且电池状态待确认时仍显示外接电源标识，充电闪电图标只跟随统一的确认状态。设置中的动画预览使用注入的模拟时间和序列，不启动额外真实采样。

## 一分钟净趋势

这一项用于避免容差掩盖持续小功率耗电，纳入完整方案；无需新增常驻轮询或弹窗告警。

使用有效、带符号、未经阈值截断的电池实测功率做时间积分：

`E_Wh = sum((P_previous + P_current) / 2 × dt_seconds / 3600)`

窗口为最近 60 秒，跨窗口边界的有效线段需裁剪。只有同一电源来源、两端有效且间隔未超出上述允许间隔的线段参与积分。冲突、估算、睡眠和长缺口不跨越；不能将最后值无限外推。结果仅为采样估算，不能用于声称测得精确电池循环损耗。

- 正积分为净充入，负积分为净放出；可另存两方向分量，但不能先取绝对值后用它表示净耗电。
- 平均净功率以有效覆盖秒数为分母，不能把缺失时间算作零；显示实际覆盖时长。
- 满 60 秒窗口且有效覆盖至少 48 秒，才标“近 1 分钟”；否则显示“观测 X 秒，数据不足”，不输出完整一分钟结论。
- 稀疏后台观测须标为低频采样估算；保持采样频率，接受无法捕获短脉冲的局限。
- 持续 −0.3 W 可能仍显示“基本闲置”，但趋势必须保留约 −0.3 W 的净放出估算，不归零。
- 最多保存约 1 分钟的有界样本队列；只在既有 tick/生命周期事件中更新。

## 验收矩阵

时间序列、缓存去重、计算服务与 reducer 已纳入自动化测试；应用目标也已构建。四种视图共享稳定后的 `PowerFlowData`，但跨机型真机视觉检查与真实 0–5 W 事件捕获仍属于 KI-001 后续工作。

| 场景 | 必须满足的结果 |
| --- | --- |
| t=0、2、4、6 秒读数均为 −2 W / −5 W | 前三次尚未确认，第四次确认辅助供电；对应正值序列确认充电 |
| 每两秒 +2、−2 交替，或夹杂零 | 不轮流提交充电/辅助供电；瞬时数值保留，方向箭头暂停 |
| 已确认 +2 W，降到 +0.8、+0.6 W | 保持充电状态，不在 1 W 边界抖动 |
| 已确认 +2 W，转为 −2 W | 首个负值即停旧箭头；负向候选从此时开始，满足四次和六秒再提交 |
| 已确认状态后出现 0 W，随后零值持续 | 首次暂停原方向，确认闲置后显示基本闲置 |
| 候选值在恰好 ±1.0、±0.5 W 处 | 使用明确边界：进入方向严格越过 ±1；绝对值 <=0.5 可确认闲置 |
| 长时间 ±0.12 W 波动 | 最多确认基本闲置；保留原始读数，不宣称硬件电流为零 |
| 单次 −5 W 后归零 | 不提交辅助供电；短脉冲仍存在于有效趋势积分中 |
| 同一采集 ID 每 0.2 秒重复发布 | 只计一次观测，不改变 EMA/积分，不提前确认 |
| 多次新读取返回相同值 | 可以累计观测；不能以值相同为由永久阻止确认 |
| 后台 10 秒间隔，t=0、10、20、30 均 −2 W | 第四次才确认；不声称从第一次起每一秒都已测到放电 |
| 间隔越界、睡眠唤醒、前后台策略改变 | 重置候选和 EMA，不跨缺口确认或积分 |
| 插拔电源但功率数据仍缓存 | 来源优先，检测到拔线即显示电池供电，不被缓存去重或旧充电候选拦住 |
| 输入未知/电池缺失/NaN/传感器冲突 | 不生成零功率闲置，不延续旧箭头，质量提示保留 |
| 只有输入与系统差值可估算电池 | 展示估算属性，不作为实测方向确认依据 |
| 持续 −0.3 W，覆盖完整一分钟 | 不被容差抹掉，净能量约 −0.005 Wh，净功率约 −0.3 W |
| 满一分钟 +2 W 与 −2 W 对称的等时序列 | 净积分按带符号数值计算；不得误报为全程 2 W 放电 |
| 数据覆盖不足一分钟/存在过长缺口 | 显示不足与覆盖时长，不假造一分钟净趋势 |
| 四种能量流视图、菜单栏、设置预览同序列 | 状态文字、颜色、方向动画一致；待确认时没有反向箭头配当前瓦数 |
| 前后台与睡眠的能耗回归 | 不新增高频 timer、SMC/IOKit 读取或后台动画；窗口内存有界 |

保留 PowerCalculationTests 中的守恒、混合供电、跨域、冲突与缺失测试，并以独立的 PowerPresentationTests 覆盖时间序列展示确认。

实施后执行 `swift test`，以及应用 Xcode 构建和上述四种视图的真机检查。量化采样/唤醒频率与当前基线比较。首轮真机回放至少涵盖插电闲置、稳定充电、插拔电源、睡眠唤醒、用户所述 0–5 W 波动；阈值以捕获数据校准，不能为了消除标签而扩大到 5 W 全部忽略。

诊断采集应为用户主动开启的短时模式，记录时间、来源、原始两种电流、所用字段、三路功率、质量、候选与最终状态；仅保留有界本地数据，不记录设备序列号。缺少实际波动记录时，发布说明只能声称展示稳定性改善，不能声称硬件根因已修复。

## 取舍与参考依据

- 不使用“电池不足 5 W 就置零”：会吞掉真实的持续辅助供电。
- 不仅替换 InstantAmperage 为 Amperage：两者当前语义和更新周期尚未在本机验证，直接替换不能解决缓存重复、状态语义及跨视图一致性。
- 不对物理功率账目强行防抖：展示策略与数值真实性必须分开。
- 第一版不叠加中值滤波、EMA、长确认窗口到同一分类通道：避免响应延迟不可预测。先用明确的阈值与时间确认，EMA 仅用于趋势；真实记录证明有需要后再调整。
- 不依据电量 80% 自动标注“优化充电中”；只在读取到已验证的系统依据时显示具体原因。

[TI bq27532-G1 技术参考](https://www.ti.com/lit/ug/sluub04/sluub04.pdf) 使用进入/退出电流阈值及时间条件区分电池工作模式，为滞回与时间确认提供工程参考；其芯片内部参数不适合作为 Mac 展示阈值。

[Analog Devices 电流寄存器波动说明](https://ez.analog.com/power/battery-management-system/a/documents/do6867/why-does-the-modelgauge-m5-current-register-jump-around-by-a-few-ma) 说明特定计量芯片的瞬时读数可能存在零均值噪声、可用平均读数核对。它不能证明这台 Mac 使用相同芯片，也不能证明本例 0–5 W 全是噪声。

[Apple 充电优化与充电上限说明](https://support.apple.com/en-au/102338) 支持“插电时可以主动暂停充电”的背景解释，不是本次瞬时正负变化的根因证据。
