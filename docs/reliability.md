# 修复与验收记录（2026-09-16）

## 已修复

- 实时供电来源被旧适配器缓存覆盖；20 W 适配器 + 10 W 电池供给 30 W 系统被误判为旁路。
- 额定功率被当作系统实时负载；无传感器时展示虚假数值。
- 适配器与系统功率来自不同测量域时误推断电池放电或阻断整个界面；现在保留原始读数，以电池控制器读数决定方向，并用系统负载生成连续可用的能量流。
- 近零电池功率按瞬时符号反复切换方向；现在按新采集 ID 去重，并使用滞回与持续时间确认。最近一分钟净趋势仍保留阈值内的微小功率。
- SMC 元数据缓存的并发访问、未知数据类型和非有限读数。
- 采样线程读取其他模块发布的可变状态；设置预览重复开启真实采样。
- 隐藏组件仍运行 top / ps，关闭面板仍保留动画计时；进程无取消管理。
- 菜单栏系统负载写死 15 W，健康度误把 mAh 当百分比、没有数据却显示“正常”。
- 设置中的后台刷新间隔不生效；删除所有组件后重启又恢复默认组件。
- 缺少登录启动控制、错误反馈和系统批准提示；登录后自动打开设置窗口。
- 清除原 Swift 编译警告，移走会被打包的 `.swift.orig` 备份。

## 本机短时观察

独立启动 Release 应用，默认后台 10 秒，未展开面板：31.52 秒内 CPU 时间增加 0.07 秒，约为单核 0.22%；常驻内存约 107.4 MB。每秒抽查一次子进程，未观察到 top / ps。

此前打开面板的 31.55 秒观察约为单核 5.74%，可观察到按需运行的 top。该样本仅用于确认前后台行为，不作为跨机型性能指标或修复前后对照实验。

本机还捕获到适配器约 12.8 W、系统约 25.2 W、电池电流为 0 的跨功率域读数。随后连续 13 次采样中，InstantAmperage 与 Amperage 始终为 0；适配器/系统差值先稳定在 −4.42 W，负载变化后稳定在 −7.51 W。这说明当前 SMC 读数不能直接用同一账目闭合，但尚未独立校准每个键的物理边界。新增的自动化回归会保留原始数值、维持电池闲置状态，并按系统负载绘制适配器供电分支，不把差值视为真实电池放电。

插电时 0–5 W 小功率正负变化的物理来源仍未捕获并确认。应用侧已避免瞬时标签和动画抖动，但这不构成硬件根因修复；证据边界及后续采集要求见 [KI-001](known-issues.md)。

## 正式发布仍需的真机验收

- 在另一台已签名安装的 Mac 上验证首次运行、登录启动、系统撤销批准和卸载。
- 插电、拔线、低功率适配器、满电旁路、充电受限、睡眠唤醒各场景逐项验收。
- 至少一次跨机型测试；目前不承诺 Intel、无电池桌面 Mac 或旧版 macOS。
- 长时间空闲、各动画样式、组件开关、最快刷新率的 CPU / Energy Impact / 唤醒次数。
- 在可用的 TSan 环境重跑测试和硬件压力场景。
- Developer ID 签名、公证与干净机器安装验收按 [发布指南](distribution.md) 执行。

短时 CPU 观察不代表长时间能耗或整机电池寿命验证；不再把“零耗电”作为已经实测达到的承诺。
